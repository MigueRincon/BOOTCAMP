Instalacion

Requisitos e instalacion

Todo lo que necesitas instalar antes de escribir una sola linea de Angular.

1. Node.js

Angular necesita Node.js para funcionar. Descargar la version LTS (Long Term Support):

Terminal
# Verificar si ya lo tienes instalado
node --version    # debe mostrar v18+ o v20+
npm --version     # viene con Node

Si no lo tienes, descargalo de nodejs.org e instala la version LTS.

2. Angular CLI

El CLI (Command Line Interface) es la herramienta que crea proyectos, genera componentes, compila y sirve la app.

Terminal
npm install -g @angular/cli

Verificar que se instalo correctamente:

Terminal
ng version

# Debe mostrar algo como:
# Angular CLI: 19.x.x
# Node: 20.x.x
🛈 Nota: Si en Windows te sale un error de permisos en PowerShell, abre PowerShell como administrador y ejecuta: Set-ExecutionPolicy RemoteSigned

3. Editor de codigo

Visual Studio Code es el estandar. Extensiones recomendadas:

ExtensionPara que sirve
Angular Language ServiceAutocompletado en templates HTML de Angular
Angular SnippetsAtajos para generar codigo rapido
PrettierFormatear codigo automaticamente

Estructura de archivos

Que es cada archivo y carpeta en un proyecto Angular.

mi-primera-app/ ├── node_modules/ ← Librerias instaladas (NO tocar) ├── src/ │ ├── app/ │ │ ├── app.component.ts ← Componente raiz (logica) │ │ ├── app.component.html ← Componente raiz (template) │ │ ├── app.component.css ← Componente raiz (estilos) │ │ ├── app.component.spec.ts ← Tests del componente │ │ ├── app.config.ts ← Configuracion de la app │ │ └── app.routes.ts ← Definicion de rutas │ ├── index.html ← HTML principal (solo uno) │ ├── main.ts ← Punto de entrada de la app │ └── styles.css ← Estilos globales ├── angular.json ← Configuracion del proyecto Angular ├── package.json ← Dependencias (como en Node) └── tsconfig.json ← Configuracion de TypeScript

Los 3 archivos clave

Cada componente en Angular se compone de 3 archivos:

ArchivoQue contieneAnalogia
.component.tsLa logica (TypeScript)El cerebro
.component.htmlEl template (HTML)El cuerpo
.component.cssLos estilos (CSS)La ropa
🛈 Importante: El CSS de cada componente es aislado. Los estilos de un componente NO afectan a otros. Esto se llama View Encapsulation.

Que es index.html?

Es el unico HTML que el navegador carga. Adentro tiene un solo tag:

src/index.html
<body>
  <app-root></app-root>
</body>

<app-root> es el componente raiz. Angular reemplaza ese tag con todo el contenido de la app. Es una Single Page Application (SPA): una sola pagina HTML donde Angular cambia el contenido dinamicamente.

Los componentes son los bloques de construccion de Angular. Todo lo que ves en pantalla es un componente.

Crear un componente

Terminal
ng generate component components/saludo

# Atajo:
ng g c components/saludo

Esto crea 4 archivos dentro de src/app/components/saludo/:

El archivo .ts (la logica)

saludo.component.ts
import { Component } from '@angular/core';

@Component({
  selector: 'app-saludo',          // el tag HTML para usar este componente
  standalone: true,                 // no necesita un modulo (Angular 17+)
  templateUrl: './saludo.component.html',
  styleUrl: './saludo.component.css'
})
export class SaludoComponent {
  nombre: string = 'Mundo';        // una propiedad (dato)
}

El archivo .html (el template)

saludo.component.html
<h1>Hola, {{ nombre }}!</h1>

Usar el componente

Para mostrar SaludoComponent dentro de AppComponent:

app.component.ts
import { Component } from '@angular/core';
import { SaludoComponent } from './components/saludo/saludo.component';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [SaludoComponent],      // importar el componente aqui
  templateUrl: './app.component.html',
  styleUrl: './app.component.css'
})
export class AppComponent {
  title = 'mi-primera-app';
}
app.component.html
<!-- Usar el componente con su selector -->
<app-saludo></app-saludo>
✓ Resultado: El navegador mostrara "Hola, Mundo!" dentro de la pagina.
⚠ Error comun: Si te sale "app-saludo is not a known element", es porque te falta importar SaludoComponent en el array imports del componente padre.

Templates y data binding

Como conectar datos del TypeScript con lo que se ve en el HTML.

Interpolacion {{ }}

Muestra el valor de una variable en el HTML:

usuario.component.ts
export class UsuarioComponent {
  nombre: string = 'Carlos';
  edad: number = 25;
  activo: boolean = true;
}
usuario.component.html
<p>Nombre: {{ nombre }}</p>
<p>Edad: {{ edad }}</p>
<p>Estado: {{ activo ? 'Activo' : 'Inactivo' }}</p>
<p>En 5 anos: {{ edad + 5 }}</p>

Property binding [ ]

Vincula una propiedad del HTML a una variable de TypeScript:

HTML
<!-- Cambiar el src de una imagen dinamicamente -->
<img [src]="urlFoto" [alt]="nombre">

<!-- Deshabilitar un boton segun una condicion -->
<button [disabled]="!activo">Enviar</button>

<!-- Agregar una clase CSS condicionalmente -->
<div [class.activo]="activo">Contenido</div>

<!-- Cambiar un estilo inline -->
<p [style.color]="activo ? 'green' : 'red'">Estado</p>

Resumen visual

SintaxisNombreDireccionEjemplo
{{ valor }}InterpolacionTS → HTMLMostrar texto
[propiedad]="valor"Property bindingTS → HTMLAtributos dinamicos
(evento)="metodo()"Event bindingHTML → TSClick, input, etc.
[(ngModel)]="valor"Two-way bindingTS ↔ HTMLFormularios
Fundamentos

Directivas: @if, @for

Las directivas controlan QUE se muestra y CUANTAS veces se repite algo en el HTML.

🛈 Angular 17+: Angular introdujo la nueva sintaxis con @if y @for en vez del antiguo *ngIf y *ngFor. Esta guia usa la nueva sintaxis, pero mas abajo se muestra la comparacion.

Condicional: @if / @else

componente.ts
export class MiComponente {
  logueado: boolean = false;
  rol: string = 'admin';
}
componente.html
@if (logueado) {
  <p>Bienvenido de vuelta!</p>
} @else {
  <p>Por favor inicia sesion</p>
}

<!-- Multiples condiciones -->
@if (rol === 'admin') {
  <p>Panel de administracion</p>
} @else if (rol === 'editor') {
  <p>Panel de edicion</p>
} @else {
  <p>Vista de usuario</p>
}

Repetir: @for

componente.ts
export class MiComponente {
  frutas: string[] = ['Manzana', 'Banana', 'Naranja'];

  usuarios = [
    { id: 1, nombre: 'Ana', activo: true },
    { id: 2, nombre: 'Luis', activo: false },
    { id: 3, nombre: 'Maria', activo: true },
  ];
}
componente.html
<!-- Lista simple -->
<ul>
  @for (fruta of frutas; track fruta) {
    <li>{{ fruta }}</li>
  }
</ul>

<!-- Lista con indice -->
@for (user of usuarios; track user.id; let i = $index) {
  <div>
    <span>{{ i + 1 }}. {{ user.nombre }}</span>
    @if (user.activo) {
      <span style="color: green"> (activo)</span>
    }
  </div>
}

<!-- Lista vacia -->
@for (user of usuarios; track user.id) {
  <p>{{ user.nombre }}</p>
} @empty {
  <p>No hay usuarios registrados</p>
}
⚠ Obligatorio: @for siempre necesita track. Usa una propiedad unica como id. Si no tienes una, usa el item mismo: track fruta.

Comparacion: sintaxis nueva vs antigua

Antigua (Angular <17)Nueva (Angular 17+)
*ngIf="condicion"@if (condicion) { }
*ngFor="let item of lista"@for (item of lista; track item) { }
[ngSwitch] + *ngSwitchCase@switch (valor) { @case }
💡 Nota: La sintaxis antigua sigue funcionando pero la nueva es la recomendada. En proyectos existentes puedes ver ambas.
Fundamentos

Eventos y two-way binding

Como capturar acciones del usuario (clicks, teclas, inputs) y como sincronizar datos en ambas direcciones.

Event binding: (evento)

contador.component.ts
export class ContadorComponent {
  contador: number = 0;

  incrementar(): void {
    this.contador++;
  }

  decrementar(): void {
    this.contador--;
  }

  reset(): void {
    this.contador = 0;
  }

  manejarTecla(event: KeyboardEvent): void {
    console.log('Tecla presionada:', event.key);
  }
}
contador.component.html
<!-- Click -->
<button (click)="decrementar()">-</button>
<span>{{ contador }}</span>
<button (click)="incrementar()">+</button>
<button (click)="reset()">Reset</button>

<!-- Eventos de teclado -->
<input (keyup)="manejarTecla($event)">
<input (keyup.enter)="buscar()">

<!-- Evento con parametro -->
<button (click)="seleccionar('rojo')">Rojo</button>
<button (click)="seleccionar('azul')">Azul</button>

Two-way binding: [(ngModel)]

Sincroniza el valor de un input con una variable. Si cambias el input, cambia la variable. Si cambias la variable, cambia el input.

Paso 1: Importar FormsModule

componente.ts
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';   // importar esto

@Component({
  selector: 'app-formulario',
  standalone: true,
  imports: [FormsModule],                        // agregar aqui
  templateUrl: './formulario.component.html'
})
export class FormularioComponent {
  nombre: string = '';
  email: string = '';
}

Paso 2: Usar en el HTML

formulario.component.html
<input [(ngModel)]="nombre" placeholder="Tu nombre">
<input [(ngModel)]="email" placeholder="Tu email">

<!-- Se actualiza en tiempo real -->
<p>Hola, {{ nombre }}! Tu email es {{ email }}</p>
🛈 Recuerda: [(ngModel)] es la combinacion de [ngModel] (property binding) + (ngModelChange) (event binding). Se le llama "banana in a box" por la forma [( )].

Comunicacion entre componentes

Como pasar datos de un componente padre a un hijo y viceversa.

Padre → Hijo: @Input()

El padre envia datos al hijo.

tarjeta.component.ts (HIJO)
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-tarjeta',
  standalone: true,
  template: `
    <div class="card">
      <h3>{{ titulo }}</h3>
      <p>{{ descripcion }}</p>
    </div>
  `
})
export class TarjetaComponent {
  @Input() titulo: string = '';
  @Input() descripcion: string = '';
}
app.component.html (PADRE)
<!-- El padre le pasa datos al hijo -->
<app-tarjeta
  titulo="Angular"
  descripcion="Framework de Google"
></app-tarjeta>

<!-- Con variables dinamicas -->
<app-tarjeta
  [titulo]="miTitulo"
  [descripcion]="miDescripcion"
></app-tarjeta>

Hijo → Padre: @Output()

El hijo le avisa al padre que algo paso (emite un evento).

boton-like.component.ts (HIJO)
import { Component, Output, EventEmitter } from '@angular/core';

@Component({
  selector: 'app-boton-like',
  standalone: true,
  template: `<button (click)="darLike()">❤ Like</button>`
})
export class BotonLikeComponent {
  @Output() liked = new EventEmitter<string>();

  darLike(): void {
    this.liked.emit('Me gusta este post!');
  }
}
app.component.html (PADRE)
<!-- El padre escucha el evento del hijo -->
<app-boton-like (liked)="manejarLike($event)"></app-boton-like>
app.component.ts (PADRE)
export class AppComponent {
  manejarLike(mensaje: string): void {
    console.log(mensaje);  // "Me gusta este post!"
  }
}
PADRE (AppComponent) │ │ [titulo]="dato" ← @Input() ← datos bajan │ (liked)="metodo()" ← @Output() ← eventos suben ▼ HIJO (TarjetaComponent)
Navegacion

Routing (rutas)

Como navegar entre "paginas" sin recargar el navegador.

Definir las rutas

app.routes.ts
import { Routes } from '@angular/router';
import { HomeComponent } from './pages/home/home.component';
import { LoginComponent } from './pages/login/login.component';
import { UsuariosComponent } from './pages/usuarios/usuarios.component';

export const routes: Routes = [
  { path: '',          component: HomeComponent },        // ruta raiz
  { path: 'login',     component: LoginComponent },
  { path: 'usuarios',  component: UsuariosComponent },
  { path: '**',        redirectTo: '' },                  // 404 -> ir al home
];

Mostrar la ruta activa

app.component.ts
import { Component } from '@angular/core';
import { RouterOutlet, RouterLink, RouterLinkActive } from '@angular/router';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [RouterOutlet, RouterLink, RouterLinkActive],
  templateUrl: './app.component.html'
})
export class AppComponent {}
app.component.html
<nav>
  <a routerLink="/"         routerLinkActive="active"
     [routerLinkActiveOptions]="{exact: true}">Home</a>
  <a routerLink="/login"    routerLinkActive="active">Login</a>
  <a routerLink="/usuarios" routerLinkActive="active">Usuarios</a>
</nav>

<!-- Aqui se renderiza el componente de la ruta activa -->
<router-outlet></router-outlet>
🛈 Importante: routerLink NO recarga la pagina (a diferencia de <a href>). Angular solo cambia el componente dentro de <router-outlet>.

Servicios y HTTP

Servicios e inyeccion de dependencias

Los servicios son clases donde pones logica que NO es visual: llamadas HTTP, manejo de datos, autenticacion. Se comparten entre componentes.

Crear un servicio

Terminal
ng generate service services/usuario

# Atajo:
ng g s services/usuario
usuario.service.ts
import { Injectable } from '@angular/core';

@Injectable({
  providedIn: 'root'    // disponible en TODA la app (singleton)
})
export class UsuarioService {
  private usuarios = [
    { id: 1, nombre: 'Ana' },
    { id: 2, nombre: 'Luis' },
  ];

  obtenerTodos() {
    return this.usuarios;
  }

  obtenerPorId(id: number) {
    return this.usuarios.find(u => u.id === id);
  }

  agregar(nombre: string) {
    const nuevo = { id: this.usuarios.length + 1, nombre };
    this.usuarios.push(nuevo);
  }
}

Usar el servicio en un componente

usuarios.component.ts
import { Component, OnInit } from '@angular/core';
import { UsuarioService } from '../../services/usuario.service';

@Component({
  selector: 'app-usuarios',
  standalone: true,
  template: `
    @for (user of usuarios; track user.id) {
      <p>{{ user.nombre }}</p>
    }
  `
})
export class UsuariosComponent implements OnInit {
  usuarios: any[] = [];

  // Angular inyecta el servicio automaticamente
  constructor(private usuarioService: UsuarioService) {}

  ngOnInit(): void {
    this.usuarios = this.usuarioService.obtenerTodos();
  }
}
Componente A ──┐ │ Componente B ──┤── UsuarioService (una sola instancia) │ │ Componente C ──┘ └── datos compartidos
💡 Por que servicios? Sin servicios, cada componente tendria su propia copia de los datos. Con un servicio, todos los componentes usan los mismos datos (singleton).
Servicios y HTTP

HttpClient y consumo de APIs

Como conectar Angular con tu backend (Express, Django, etc.) usando peticiones HTTP.

Paso 1: Configurar HttpClient

app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(),       // habilitar HttpClient
  ]
};

Paso 2: Servicio con peticiones HTTP

usuario.service.ts
import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

interface Usuario {
  _id: string;
  nombre: string;
  email: string;
}

@Injectable({ providedIn: 'root' })
export class UsuarioService {
  private apiUrl = 'http://localhost:3000/api/usuarios';

  constructor(private http: HttpClient) {}

  // GET - Obtener todos
  obtenerTodos(): Observable<Usuario[]> {
    return this.http.get<Usuario[]>(this.apiUrl);
  }

  // GET - Obtener uno por ID
  obtenerPorId(id: string): Observable<Usuario> {
    return this.http.get<Usuario>(`${this.apiUrl}/${id}`);
  }

  // POST - Crear
  crear(usuario: { nombre: string; email: string }): Observable<Usuario> {
    return this.http.post<Usuario>(this.apiUrl, usuario);
  }

  // PUT - Actualizar
  actualizar(id: string, datos: Partial<Usuario>): Observable<Usuario> {
    return this.http.put<Usuario>(`${this.apiUrl}/${id}`, datos);
  }

  // DELETE - Eliminar
  eliminar(id: string): Observable<any> {
    return this.http.delete(`${this.apiUrl}/${id}`);
  }
}

Paso 3: Usar en el componente

usuarios.component.ts
export class UsuariosComponent implements OnInit {
  usuarios: any[] = [];
  cargando: boolean = true;
  error: string = '';

  constructor(private usuarioService: UsuarioService) {}

  ngOnInit(): void {
    this.usuarioService.obtenerTodos().subscribe({
      next: (data) => {
        this.usuarios = data;
        this.cargando = false;
      },
      error: (err) => {
        this.error = 'Error al cargar usuarios';
        this.cargando = false;
        console.error(err);
      }
    });
  }

  eliminar(id: string): void {
    this.usuarioService.eliminar(id).subscribe({
      next: () => {
        this.usuarios = this.usuarios.filter(u => u._id !== id);
      },
      error: (err) => console.error(err)
    });
  }
}
⚠ Clave: http.get() NO hace la peticion inmediatamente. Retorna un Observable. La peticion se ejecuta cuando llamas .subscribe().
Servicios y HTTP

Observables (RxJS basico)

Los Observables son como promesas pero mas poderosas. En Angular, todo lo async (HTTP, eventos, timers) usa Observables.

Observable vs Promise

CaracteristicaPromiseObservable
ValoresEmite 1 valorPuede emitir muchos valores
CancelableNoSi (unsubscribe)
EjecucionInmediataLazy (solo cuando hay subscribe)
OperadoresSolo .then/.catchmap, filter, debounce, retry, etc.

Patron basico

componente.ts
// Subscribirse a un Observable
this.miServicio.obtenerDatos().subscribe({
  next: (datos) => {
    // se ejecuta cuando llegan los datos
    this.datos = datos;
  },
  error: (err) => {
    // se ejecuta si hay un error
    console.error(err);
  },
  complete: () => {
    // se ejecuta cuando termina (opcional)
    console.log('Completado');
  }
});

Pipe async (alternativa al subscribe)

En vez de subscribirte manualmente, puedes usar el pipe async en el HTML:

componente.ts
import { AsyncPipe } from '@angular/common';
import { Observable } from 'rxjs';

@Component({
  imports: [AsyncPipe],
  template: `
    @for (user of usuarios$ | async; track user._id) {
      <p>{{ user.nombre }}</p>
    }
  `
})
export class UsuariosComponent implements OnInit {
  usuarios$!: Observable<Usuario[]>;   // el $ es convencion para Observables

  constructor(private usuarioService: UsuarioService) {}

  ngOnInit(): void {
    this.usuarios$ = this.usuarioService.obtenerTodos();
    // no hay .subscribe() - el pipe async lo hace automaticamente
  }
}
✓ Ventaja de async pipe: Se desubscribe automaticamente cuando el componente se destruye. No hay riesgo de memory leaks.

Operadores utiles de RxJS

ejemplo-operadores.ts
import { map, catchError, tap, debounceTime } from 'rxjs/operators';
import { of } from 'rxjs';

// map: transformar datos
this.http.get<any[]>(url).pipe(
  map(users => users.filter(u => u.activo))
);

// catchError: manejar errores sin romper el flujo
this.http.get(url).pipe(
  catchError(err => {
    console.error(err);
    return of([]);   // retornar array vacio en caso de error
  })
);

// tap: hacer algo sin modificar los datos (para debug/logging)
this.http.get(url).pipe(
  tap(data => console.log('Datos recibidos:', data))
);

Template-driven forms

La forma mas sencilla de manejar formularios. Ideal para formularios simples (login, registro, contacto).

Setup

login.component.ts
import { Component } from '@angular/core';
import { FormsModule } from '@angular/forms';

@Component({
  selector: 'app-login',
  standalone: true,
  imports: [FormsModule],
  templateUrl: './login.component.html'
})
export class LoginComponent {
  email: string = '';
  password: string = '';

  onSubmit(): void {
    console.log('Email:', this.email);
    console.log('Password:', this.password);

    // Aqui llamarias al servicio de login
  }
}

🛈 Puntos clave:
  • #loginForm="ngForm" — referencia al formulario completo
  • #emailField="ngModel" — referencia a un campo individual
  • .invalid, .touched, .dirty — estados del campo
  • (ngSubmit) — evento que se dispara al enviar el form

Reactive forms

La forma avanzada de manejar formularios. Toda la logica vive en el TypeScript (mas control, mas testeable).

Setup

registro.component.ts
import { Component } from '@angular/core';
import { ReactiveFormsModule, FormGroup, FormControl, Validators } from '@angular/forms';

@Component({
  selector: 'app-registro',
  standalone: true,
  imports: [ReactiveFormsModule],
  templateUrl: './registro.component.html'
})
export class RegistroComponent {

  // Definir el formulario en el TypeScript
  registroForm = new FormGroup({
    nombre:   new FormControl('', [Validators.required, Validators.minLength(3)]),
    email:    new FormControl('', [Validators.required, Validators.email]),
    password: new FormControl('', [Validators.required, Validators.minLength(6)]),
    edad:     new FormControl(0,  [Validators.required, Validators.min(18)]),
  });

  onSubmit(): void {
    if (this.registroForm.valid) {
      console.log(this.registroForm.value);
      // { nombre: 'Ana', email: 'ana@mail.com', password: '123456', edad: 25 }
    }
  }
}

Validator personalizado

validators/no-espacios.validator.ts
import { AbstractControl, ValidationErrors } from '@angular/forms';

export function noEspaciosValidator(control: AbstractControl): ValidationErrors | null {
  if (control.value && control.value.includes(' ')) {
    return { noEspacios: true };   // retornar un objeto = invalido
  }
  return null;                      // retornar null = valido
}

Auth y Proteccion

Interceptors (enviar JWT automaticamente)

Un interceptor se mete en TODAS las peticiones HTTP automaticamente. Perfecto para enviar el token JWT en cada request sin repetir codigo.

Crear el interceptor

interceptors/auth.interceptor.ts
import { HttpInterceptorFn } from '@angular/common/http';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  // Obtener el token del localStorage
  const token = localStorage.getItem('token');

  if (token) {
    // Clonar la peticion y agregarle el header Authorization
    const cloned = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`
      }
    });
    return next(cloned);
  }

  // Si no hay token, dejar pasar la peticion sin modificar
  return next(req);
};

Registrar el interceptor

app.config.ts
import { provideHttpClient, withInterceptors } from '@angular/common/http';
import { authInterceptor } from './interceptors/auth.interceptor';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes),
    provideHttpClient(
      withInterceptors([authInterceptor])    // registrar aqui
    ),
  ]
};

Servicio de autenticacion

services/auth.service.ts
import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Router } from '@angular/router';
import { tap } from 'rxjs/operators';

@Injectable({ providedIn: 'root' })
export class AuthService {
  private apiUrl = 'http://localhost:3000/api';

  constructor(private http: HttpClient, private router: Router) {}

  login(email: string, password: string) {
    return this.http.post<{ token: string }>(`${this.apiUrl}/login`, { email, password })
      .pipe(
        tap(res => {
          localStorage.setItem('token', res.token);
        })
      );
  }

  logout(): void {
    localStorage.removeItem('token');
    this.router.navigate(['/login']);
  }

  isLoggedIn(): boolean {
    return !!localStorage.getItem('token');
  }

  getToken(): string | null {
    return localStorage.getItem('token');
  }
}
Auth y Proteccion

Guards (rutas privadas)

Los guards protegen rutas. Si el usuario no esta logueado, lo redirigen al login.

Crear un guard

guards/auth.guard.ts
import { inject } from '@angular/core';
import { CanActivateFn, Router } from '@angular/router';
import { AuthService } from '../services/auth.service';

export const authGuard: CanActivateFn = (route, state) => {
  const authService = inject(AuthService);
  const router = inject(Router);

  if (authService.isLoggedIn()) {
    return true;           // dejar pasar
  }

  router.navigate(['/login']);
  return false;             // bloquear y redirigir
};

Aplicar el guard a las rutas

app.routes.ts
import { authGuard } from './guards/auth.guard';

export const routes: Routes = [
  { path: 'login',     component: LoginComponent },          // publica
  { path: '',          component: HomeComponent },            // publica

  // Rutas protegidas
  { path: 'dashboard', component: DashboardComponent, canActivate: [authGuard] },
  { path: 'usuarios',  component: UsuariosComponent,  canActivate: [authGuard] },
  { path: 'perfil',    component: PerfilComponent,    canActivate: [authGuard] },

  { path: '**', redirectTo: '' },
];
Usuario navega a /dashboard │ ▼ ┌───────────────────┐ │ AUTH GUARD │ │ Tiene token? │ └───────────────────┘ │ │ SI ▼ NO ▼ Dashboard /login
✓ Flujo completo: El guard verifica si hay token → El interceptor lo envia en cada request → El backend valida el token con su middleware.

Pipes (transformar datos)

Los pipes transforman datos en el template sin modificar el valor original.

Pipes incluidos en Angular

componente.html
<!-- Texto -->
<p>{{ 'hola mundo' | uppercase }}</p>          <!-- HOLA MUNDO -->
<p>{{ 'HOLA MUNDO' | lowercase }}</p>          <!-- hola mundo -->
<p>{{ 'hola mundo' | titlecase }}</p>          <!-- Hola Mundo -->

<!-- Numeros -->
<p>{{ 3.14159 | number:'1.2-2' }}</p>          <!-- 3.14 -->
<p>{{ 0.85 | percent }}</p>                     <!-- 85% -->
<p>{{ 1500 | currency:'COP' }}</p>              <!-- COP1,500.00 -->
<p>{{ 1500 | currency:'USD':'symbol' }}</p>     <!-- $1,500.00 -->

<!-- Fechas -->
<p>{{ hoy | date:'short' }}</p>                 <!-- 6/11/26, 3:30 PM -->
<p>{{ hoy | date:'fullDate' }}</p>              <!-- Wednesday, June 11, 2026 -->
<p>{{ hoy | date:'dd/MM/yyyy' }}</p>            <!-- 11/06/2026 -->

<!-- JSON (debug) -->
<pre>{{ usuario | json }}</pre>
🛈 Imports: Para usar estos pipes, importa CommonModule o cada pipe individual (UpperCasePipe, DatePipe, etc.) en tu componente standalone.

Terminal

import { Pipe, PipeTransform } from '@angular/core';

@Pipe({
  name: 'truncar',
  standalone: true
})
export class TruncarPipe implements PipeTransform {
  transform(valor: string, limite: number = 50): string {
    if (valor.length <= limite) return valor;
    return valor.substring(0, limite) + '...';
  }
}

Ciclo de vida de un componente

Angular ejecuta funciones especiales en momentos clave de la vida de un componente.

constructor() ← Se crea la instancia (NO hacer logica aqui) │ ngOnInit() ← Se inicializa el componente (CARGAR datos aqui) │ ngOnChanges() ← Un @Input() cambio de valor │ ngDoCheck() ← Angular revisa si algo cambio │ ngAfterViewInit() ← La vista (HTML) ya esta renderizada │ : (la app sigue corriendo...) │ ngOnDestroy() ← El componente se va a destruir (LIMPIAR aqui)

Los 3 que mas vas a usar

mi-componente.ts
import { Component, OnInit, OnDestroy, Input, OnChanges, SimpleChanges } from '@angular/core';
import { Subscription } from 'rxjs';

export class MiComponente implements OnInit, OnDestroy, OnChanges {
  @Input() userId!: string;
  private sub!: Subscription;

  // 1. Se ejecuta UNA vez cuando el componente se crea
  ngOnInit(): void {
    console.log('Componente inicializado');
    this.sub = this.miServicio.obtenerDatos().subscribe(data => {
      this.datos = data;
    });
  }

  // 2. Se ejecuta cada vez que un @Input() cambia
  ngOnChanges(changes: SimpleChanges): void {
    if (changes['userId']) {
      console.log('userId cambio de', changes['userId'].previousValue,
                   'a', changes['userId'].currentValue);
    }
  }

  // 3. Se ejecuta cuando el componente se destruye
  //    (cambiaron de ruta, un *ngIf lo oculto, etc.)
  ngOnDestroy(): void {
    console.log('Componente destruido');
    this.sub.unsubscribe();   // LIMPIAR subscripciones para evitar memory leaks
  }
}
💡 Regla de oro:
  • ngOnInit → cargar datos, subscribirse a observables
  • ngOnDestroy → desubscribirse, limpiar timers
  • constructor → SOLO para inyectar servicios, nada mas
